# WO-08 — Strip dead surface

> Priority: P1 · Depends on: nothing · Status: executed 2026-08-27
> Scope: `cover_note` generation, Adzuna in the GB pack, the Teamtailor
> scraper. Everything here is dead weight every later work order carries.

## What and why

1. **`cover_note`** — generated by the scoring prompt on every match,
   stored, returned by the API… and rendered nowhere in the frontend. Its
   prompt instructions (VOICE exception block + JSON schema entry + output
   tokens per match) are ~20% of the scoring bill. The real cover letter
   is written later, per-application, by `tailor_application` — the
   scoring-time note was speculative work paid for in advance and never
   consumed. **The `match_results.cover_note` column stays** (nullable,
   holds historical rows); nothing generates, writes, exposes, or types it.
2. **Adzuna in the GB pack** — the recorded verdict was "demote, don't
   delete": in the UK, Reed carries the market and Adzuna is redundant
   garnish burning scrape quota on every hunt; at US/AU expansion Adzuna
   IS the backbone, so the scraper module and registry entry remain for
   those packs. Only the pack membership changes.
3. **Teamtailor** — dead without `TEAMTAILOR_SITES`, which has never been
   configured. Full removal: pack entry, registry entry, module, config
   key, tests.

## Consequences to carry forward

- **This is a prompt change.** `matching_prompt_version()` is a hash of
  the prompt text; removing the cover_note instructions changes the hash,
  so new scoring runs stamp a new version. Per the standing rule ("treat
  it like a prompt change: version it, never mix scales in one queue"),
  the backlog re-score this triggers is **WO-09** (~$0.33 at verified
  pricing). Removing an output field should not move scores — WO-09's
  before/after diff is the evidence.
- Historical `cover_note` values remain in the DB, unexposed. Dropping
  the column would be a destructive migration for zero gain.

## Acceptance criteria (grep-provable)

1. The matching prompt contains no `cover_note` instruction or schema
   entry. Test: `_build_matching_prompt()` output asserted clean.
2. No code path generates, writes, or API-exposes `cover_note`
   (`grep -rn cover_note backend/app frontend/src` → only the model
   column and comments).
3. `MatchResponse` has no `cover_note` field; frontend `Match` type
   drops it; `tsc --noEmit` and `next build` green.
4. GB pack scrapes `["reed", "careerjet", *SHARED_REMOTE_SOURCES]` —
   no Adzuna. Scraper module retained, still registered.
5. No `teamtailor` anywhere in `backend/app/` (module deleted, registry
   entry gone, config key gone).
6. Full suite green on SQLite and Postgres CI legs; revert-checks red
   against each restored defect.
