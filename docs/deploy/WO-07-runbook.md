# WO-07 — Production Deployment Runbook (Render + Cloudflare Pages)

Status: **Step 1 DONE** (2026-08-28 — bucket `cvs` created + verified
private via `ops/provision_supabase_storage.py`; SUPABASE_* uncommented
in `backend/.env`). Steps 2–4 are the remaining dashboard work.

## Topology & monthly cost

| Piece | Where | Plan | Cost |
|---|---|---|---|
| API (FastAPI, Docker) | Render web service `jobfinderos-api` | free (512MB, spins down after 15 min idle, ~1 min cold start) | $0 |
| Hunt (scrape → match → …) | Render cron job `jobfinderos-hunt`, hourly, one-shot `worker --once` | 0.5c-512mb, metered per second ($1/mo minimum) | ~$1–3 |
| Postgres | Supabase (WO-03), session pooler | free tier | $0 |
| Frontend | Cloudflare Pages, static export | free | $0 |
| CV storage | Supabase Storage, private `cvs` bucket | free tier (1GB) | $0 |

Design decisions and their doc sources are commented inline in
`render.yaml`, `backend/Dockerfile.hunt`, and `frontend/next.config.ts`.

Key decisions:
- **Cron, not a 24/7 worker** — cron bills per second of active runtime
  (render.com/docs/cronjobs); a scheduler loop would bill ~$7/mo.
  `worker --once` claims the DB hunt lock, runs one cycle, exits.
- **Boot migrations, advisory-locked** — `preDeployCommand` requires a
  paid plan (render.com/docs/deploys), so migrations run at boot;
  `init_db` serializes concurrent boots with `pg_advisory_lock` (verified
  by an API/cron boot race against an empty Postgres — see commit).
- **Static frontend** — the app is fully client-side; CF Pages serves
  `out/` via the official "Next.js (Static HTML Export)" preset
  (developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site).
- **Supabase storage for CVs** — Render's free filesystem is ephemeral
  (lost on every deploy/restart/spin-down; render.com/docs/free).
- **Frankfurt region** — keeps the API→Supabase (eu-west-1) data path
  intra-EU. If Frankfurt is unavailable for free instances at creation
  time, choose **oregon** (latency is fine) and note it here.

## Step 2 — Render blueprint

1. Render dashboard → **New → Blueprint**, select the GitHub repo.
   Render reads the committed `render.yaml` and creates both services.
2. Fill the prompted secrets (`sync: false` — asked once, stored by
   Render). Every value already exists in `backend/.env` — copy from
   there, one prompt at a time:

| Prompt | Where the value lives (backend/.env) |
|---|---|
| `DATABASE_URL` (api + cron) | `DATABASE_URL` — the `...aws-1-eu-west-1.pooler.supabase.com:5432/postgres` line |
| `GLM_API_KEY` (api + cron) | `GLM_API_KEY` |
| `CORS_ORIGINS` (api) | type it: `https://jobfinderos.pages.dev` (add custom domains later, comma-separated) |
| `SUPABASE_URL` (api) | `SUPABASE_URL` |
| `SUPABASE_SERVICE_KEY` (api) | `SUPABASE_SERVICE_KEY` |
| `JOBTECH_API_KEY` / `REED_API_KEY` (api + cron) | same-named lines (empty prompt = source self-disables) |
| `SENTRY_DSN` (api + cron) | leave empty (off) |

`AUTH_SECRET` is auto-generated by Render (`generateValue`) on both
services and persists across deploys.

3. Apply. The API must pass `/health` (DB connectivity) before traffic
   routes; a failed check fails the deploy (render.com/docs/health-checks).

## Step 3 — Cloudflare Pages

1. Cloudflare dashboard → **Workers & Pages → Create → Pages → Import an
   existing Git repository** → pick the repo, production branch `main`.
2. Build settings (official static-export preset):
   - Framework preset: **Next.js (Static HTML Export)**
   - Build command: `npx next build`
   - Build output directory: `out`
   - Root directory (advanced): `frontend`
3. Environment variables (Settings → Variables):
   - `NEXT_PUBLIC_API_URL` = `https://jobfinderos-api.onrender.com`
   - `NODE_VERSION` = `20`
4. Save & Deploy. Note the project URL (`https://<project>.pages.dev`).
   If it differs from `jobfinderos.pages.dev`, update `CORS_ORIGINS` on the
   Render API (dashboard → Environment) to match.

## Step 4 — post-deploy verification

One command checks every gate (health, CORS preflight, a live
register/login roundtrip, and the Pages bundle's inlined API URL):

```sh
bash ops/verify_deployment.sh
```

Manual spot-checks if you prefer:

```sh
curl https://jobfinderos-api.onrender.com/health        # {"status":"ok","database":"up",...}
# In the browser: open the pages.dev URL → register → login → upload CV
```

- Render → `jobfinderos-hunt` → check the first hourly run's logs:
  `One-shot hunt complete: {'status': 'ran', 'users': N, 'errors': 0}`.
- Trigger a manual run from the cron service's dashboard to avoid
  waiting for the top of the hour.
- First request after idle takes ~1 min (free-instance cold start) —
  that is the documented free-plan behavior, not an outage.

## Operations

- **Backups** stay as-is: `ops/backup.sh` (pg_dump of Supabase + off-site
  B2) runs nightly from the Mac via launchd. Render does not run our
  backups; the cron job is the hunt only.
- **Cost ceiling**: ~$1–3/mo total until a paid instance is justified.
  Growth path: upgrade the API instance first (cold starts hurt more than
  hunt latency), keep the cron shape until hunts exceed ~10 h/month of
  runtime, then compare with a 24/7 worker.
- **Secrets rotation**: everything prompted in Step 2 lives in Render's
  dashboard — rotate there, then redeploy. Never put real values in
  `render.yaml` (CI enforces this).
